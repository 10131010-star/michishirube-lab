# 月商100万円に向けたBtoB受託・販売実験（仮説、未公開）

更新: 2026-11-14 / 対象: 既存Web/LP制作事業 / 既存のPR #29と既存販売商品を活用
**これは売上予測・正式見積ではなく、目標から逆算した検証用の事業計画です。** 月商と個人の手取り・純利益は異なる。

## 2026-11-14 方針更新：売上より実際に残る利益を優先

オーナー承認：**追加の本人作業が必要でも、増分利益が大きければその案を優先してよい**。ただし顧客への営業メール・DM送信は禁止のまま。既存GmailのB2B転用は禁止。BOOTH 980円商品のタイトル・冒頭文・真正Unity画像の改善は承認済み、価格・配布ZIP差替えは禁止。広告・課金・新規アカウント/決済・契約・本人申告は別承認が必要。

**第一順位：確定した税引前利益・限界利益、第二順位：入金、第三順位：受注、第四順位：有効問い合わせ。** 月商100万円は維持するが、赤字受注や安値の過剰納品で達成しない。

### 各案件の採算判定（実費不明なら仮説と明記）
| 指標 | 算出方法 | 不明時 |
| --- | --- | --- |
| 売上額 | 実入金／確定請求を別記。税込と税抜を区別 | unknown |
| 直接原価 | 外注費、決済・プラットフォーム手数料、案件固有の有料API・素材・配信費 | unknown |
| 限界利益 | 税抜売上−直接原価 | 原価が不明なら算定不可 |
| 本人作業時間 | 商談、顧客確認、制作、修正、納品 | 実測開始までunknown |
| AI実行コスト | 対象案件のAPI/サービスの従量利用料金 | 定額費と按分費を区別 |
| 実効時間利益 | 限界利益÷本人の作業時間 | 事前にはシナリオ比較のみ |
| 回収速度 | 初回入金までの日数・見込確度 | 根拠がなければunknown |

- **例示**：仮に98,000円の案件が直接原価8,000円、本人作業10時間なら限界利益90,000円、時間利益9,000円。これは想定例であり実測値ではない。1件の98,000円案件より、198,000円で40時間の案件が常に優れるわけではない。
- 初回は**客先の困りごとを確認したサービス1件**を優先。納品までの必要時間/修正回数/保守コストを見積もる。正式見積と相手の合意を経るまで料金は確定しない。
- 1案件あたり利益が増える明確な見込みがある場合、オーナーの**手動商談・商品ページでの本人登録・正式な個別契約判断**を提案してよい。ただし無断で顧客接触・契約・課金しない。作業依頼は「必要時間・期待する増分利益・証拠・実行期限・やらない場合の機会損失」を付けてまとめ、繰り返し質問しない。
- 利益率が悪い商品・追加実装は縮小。広告費は採算確認前に投入しない。特に980円のBOOTH商品で必要有料顧客獲得費を不明のまま広告運用しない。
- 事業を増やす条件は**支払意思の証拠、実際の顧客接点、限界利益、納品能力、販売開始までの短さ**で既存案件を上回ること。収益証拠なしの新規SaaS量産は回避。

## 月商目標から逆算した「必要成約件数」の算術例
- **高単価の仮説**：198,000円×5件＋39,800円×1件＝**1,029,800円**。ただし5件の自動化案件の納期・人件費・品質を満たせるか未確認。
- **中単価の仮説**：98,000円×8件＋39,800円×6件＝**1,022,800円**。14件の納品能力が必要で、現状の実績では到達可能性を保証できない。
- **スターターだけ**：39,800円×26件＝**1,034,800円**。大量の制作・獲得が必要で初期の推奨ではない。
- **BOOTH 980円だけ**：980円×1,021件＝**1,000,580円**。手数料前であり、今の実測訪問数からは非現実的な規模。BOOTHは販売と信頼の蓄積を主眼にする。

最初は高単価案件をいきなり作り込むのではなく、既存の39,800円案への相談/支払意思を確認し、**実際の顧客課題に応じた上位見積**を提案する。

## 受注の仮説とデータ計測
- 要確認の指標: ①許可された経路での表示/到達 ②訪問 ③有効問い合わせ ④ヒアリング完了 ⑤正式見積 ⑥成約 ⑦請求 ⑧入金 ⑨原価 ⑩限界利益
- 初期仮説: 相談から成約20%と仮に置くなら、5件成約には25件の有効相談が必要。**20%は経験的な成約率ではなく仮置き**。未計測なら不明と明示し、顧客属性と相談品質に応じて更新。
- 週次で、最も失敗している1段階（SNS→LP、LP→相談、相談→見積、見積→成約など）だけに絞って改修する。
- GitHub PRのマージ件数・AI実行回数・テンプレート作成件数は売上KPIではない。
- 相手からの問い合わせがない場合、広告増額より先に顧客の課題、提供価値、案内先と申込経路を見直す。

## 4週間の実証工程
**Week 1**：スターターLP/デモ/5項目診断を権利・連絡先・価格条件まで整える。許可済みの営業先/紹介から5件の具体的課題をヒアリングする準備。実問い合わせ1件を仮説目標にする。**無承認の第三者送信はしない。**
**Week 2**：相談から見積に進んだ案件の対象課題と予算を比較。需要がある場合だけ98,000円/198,000円案の個別見積・最小デモを作り、許可済みの接点で検証。
**Week 3**：受注済みの納品工程から反復可能部分をCodexで半自動化。Claudeで独立レビュー、リンク/権利/表示テスト。広告出稿でなく実際の紹介・顧客満足を優先。
**Week 4**：入金と実際の制作工数/追加費用を計測。少額商品のBOOTH・note/KDPの購入実績も加えて目標との差額を分析。成功した案件だけ集客・納品工程を拡張する。

## 未完了の販売ゲート
正式な問い合わせ先、事業者表示、価格/修正回数/納期/契約条件、既存アカウントを使う投稿/営業連絡の明示的な許可、顧客情報の安全な管理。未確定の間は別の販売可能な既存商品や商談素材へ移り、勝手に広告・DM・契約・決済・新規アカウント作成をしない。
