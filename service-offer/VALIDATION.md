# 小規模店舗のWeb集客・問い合わせ導線改善パック｜7日間の販売検証

## 目的と位置づけ
低価格デジタル商品だけでなく、最短で初受注が狙えるBtoBサービスを検証する。**販売開始・営業送信・決済契約ではなく、需要確認用の初期オファー草案**。

公開中の無料診断/BOOTH商品/ノートは既存プロジェクトに維持する。既存のLP事業と顧客層が重なるため、別の新規事業を増やさずLP/HP制作の一商品として扱う。

## オファー
- 顧客：大阪の小規模飲食店、個人サロン、地域サービス店。まずは1業種に絞る。
- 課題：SNS、Googleマップ、予約/問い合わせ先が分散しており、顧客が次の行動を取りにくい。
- 提供：既存チャネル診断、スマホ向け案内ページ1枚、地図/予約/問い合わせリンク検証、簡単な計測方針。
- 仮説価格：税込39,800円の買い切り。正式見積・納期・修正回数・素材権利・保守条件は要確認。固定価格として確約しない。
- 除外：広告費、SNSアカウント運用、予約代行、Googleビジネスプロフィールの無許可変更、継続保守。
- 初期成果の証拠：完了したデモ、リンク検証結果、正式な顧客問い合わせ/受注記録（許可なく個人情報を保存しない）。

## 採用した収益モデルの根拠と限界
実売上を開示した個人/小規模事業の例では、業務受託やBtoB顧客への具体的価値提供から収益を得て、繰り返し作業をAIで自動化している。これは顧客ニーズを確かめる方針の根拠にはなるが、本オファーの支払意思・適正価格は未知。AIを使うこと自体を販売価値として誇張しない。

## 7日間の検証計画
| 日程 | 具体行動 | 完了証拠 |
| --- | --- | --- |
| D1 | 提供条件、LP草案、想定課題3つを準備 | GitHub PR、動作チェック |
| D2 | 店舗の実データなしの汎用デモを1つ作る | 著作権を守ったデモURL（公開は承認内のみ） |
| D3 | 受付先と事業者表示・個人情報方針を確定 | オーナーの承認記録 |
| D4 | 承認された範囲の既存SNS/紹介で役立つ例を発信 | 実投稿URL、件数 |
| D5 | 正式な問い合わせ/相談経路を検証 | 実テスト記録 |
| D6 | 実際の問い合わせ・見積・回答率を確認 | 許可された匿名集計 |
| D7 | 受注・利益・需要の証拠で継続/修正/停止を判断 | 7日レビュー |

## 事前の成功/失敗条件
- 重要KPI：有効問い合わせ → 見積希望 → 受注、1件当たりの想定粗利益、対応時間。
- 先行KPI：ページの実測訪問、CTAクリック、価格/提供内容への質問。
- 初期判定は「7日で少なくとも有効問い合わせ1件」を検証仮説とする。問い合わせが来なければ直ちに価格の安さだけが原因とは推論しない。小標本のため結論は暫定的。
- **ユーザーが閲覧した回数、GitHubコミット、SNS下書きを問い合わせ・購入として計上しない**。

## 事前承認の必要事項
- 実際に顧客が連絡するための受信先（個人/事業用メール、フォームなど）。新規に偽の連絡先を作らない。
- 公開する事業者名・連絡先・必要な事業者表示。
- 対外公開、見積条件、SNS/営業送信の範囲。
- 広告は予算・損益分岐と配信可否の承認があるまで不可。

## AI分担
- ChatGPT/Dots：顧客の課題仮説と販売指標の検証、次のアクション選定。
- Codex：顧客向けLP/デモ/リンク・モバイル検査と安全なPR作成。
- Claude Code：権利・提供条件・誇大表現・問い合わせ導線の独立レビュー。
- 人間：対外連絡先/正式価格/契約/商談・公開の承認。
- 最小自動ループ：PR→動作検査→承認済み公開→実測集客→問い合わせ→改善。新しい管理OSは作らない。
